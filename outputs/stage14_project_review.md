# CIFAR-10 项目技术说明

整理日期：2026-10-08（Asia/Shanghai）。本文根据源码、配置和实验记录，说明模型结构、训练与评估流程、对照实验、配置修改及排错方法。

所选最佳模型的官方测试准确率为81.48%（8,148/10,000），平均loss为0.550410。见[评估记录](stage15_test_20261008_002741_012201/evaluation_summary.md)。

下文的排错例子及10轮配置修改场景属于源码分析，未执行这些假设实验。

## 1. 从入口到结果的完整流程

以 [stage12_compare_lr.py](../stage12_compare_lr.py) 为例：

```text
main：读取已有训练/验证索引，准备数据和共同初始模型状态
  ↓ 分别启动A、B两组
run_group：创建本组模型与新Adam，复制共同初值
  ↓ 每轮调用
train_one_epoch：遍历训练批次，计算梯度并更新参数
  ↓ 每轮训练后调用
evaluate：用固定的轮末模型统计训练与验证表现
  ↓
run_group：记录指标，按验证准确率保存best，结束保存last
  ↓ 两组结束
main：写入comparison.json，比较验证表现
```

| 函数 | 主要输入 | 输出与作用 |
| --- | --- | --- |
| `main()` | 命令行开关、本地数据、已有划分及历史配置 | 组织两组实验并保存比较结果；默认模式只打印计划 |
| `run_group()` | 本组名称、学习率、共同初始状态、数据和设备 | 返回本组指标与权重路径；管理轮数、评估和保存 |
| `train_one_epoch()` | 模型、训练loader、损失函数、优化器、设备及当前轮号 | 返回平均训练loss、处理的图片数、实际更新次数 |
| `evaluate()` | 模型、待评估loader、损失函数和设备 | 返回平均loss、accuracy、正确图片数、图片总数 |

训练函数复用自 [stage10_train_compare.py](../stage10_train_compare.py)，评估函数复用自 [stage6_evaluate.py](../stage6_evaluate.py)。因此定位问题时，既要看入口，也要看被调用函数的实现。

## 2. 数据、batch、epoch 与 Tensor shape

当前对照使用40,000张训练图片、10,000张验证图片。索引保存于 [固定划分文件](stage9_split_seed42.json)，每类分别为4,000与1,000张；各实验复用同一文件。

一个batch是一次送入模型的图片集合，一个epoch是训练loader完整遍历一轮。当前batch_size=8，因此每轮5,000批、5轮共25,000次参数更新。评估批次不计入优化器更新次数。

| 对象 | 当前batch=8 | 假设batch=64 | 含义 |
| --- | --- | --- | --- |
| 图片 | `[8,3,32,32]` | `[64,3,32,32]` | 图片数量、RGB通道、高度、宽度 |
| 标签 | `[8]` | `[64]` | 每张图片一个真实类别编号 |
| logits | `[8,10]` | `[64,10]` | 每张图片对应10个类别分数 |
| 预测编号 | `[8]` | `[64]` | 每行最大分数所在的类别位置 |
| 平均loss | 标量 | 标量 | 当前批次的损失汇总 |

若只把batch从8改成16，40,000张图片每轮变为2,500批，5轮为12,500次更新。训练轮数相同，更新次数也会改变；比较结果时应同时记录这些条件。标签、模型输出的首维随实际批次大小变化，10类输出维度保持不变。

## 3. 为什么使用 CNN，ResNet18 改了什么

卷积在局部区域提取特征，同一组卷积核在不同位置共享参数。例如，识别轮廓边缘的卷积核可以在图片的多个位置使用。局部结构和参数共享适合图像任务，但模型实际学到了什么仍需结合结果分析，不能仅凭模型名称确认。

[SimpleCNN](../models/simple_cnn.py) 使用两组卷积、ReLU和最大池化，再接全连接层：`[B,3,32,32] → [B,16,16,16] → [B,32,8,8] → [B,2048] → [B,64] → [B,10]`。参数量为136,874。

[适配ResNet18](../models/resnet18_cifar.py) 从随机初始化开始，未使用预训练权重。入口卷积改为3×3、stride=1，入口最大池化替换成Identity，最后全连接输出10类；这样避免32×32图片在入口过快缩小。参数量为11,173,962。

残差连接在相容尺寸下把输入与变换后的特征相加，即 `x + F(x)`，为信息和梯度提供额外路径。本项目观察到的是适配ResNet18整体配置的表现，不能把全部准确率差异单独归因于残差连接。

## 4. 一批图片如何训练

现有训练函数的关键步骤是：

```python
optimizer.zero_grad(set_to_none=True)
outputs = model(images)
loss = criterion(outputs, labels)
loss.backward()
optimizer.step()
```

`images` 输入为 `[B,3,32,32]`，`outputs` 为 `[B,10]`。`criterion` 是CrossEntropyLoss，接收logits和 `[B]` 的整数标签，输出标量loss；计算损失前不手动添加Softmax。

清空梯度是因为PyTorch默认会累积梯度；`backward()`计算本次损失对参数的梯度，`step()`使用梯度及优化器状态更新参数。仅做forward不会自动学习，仅做backward也不会执行优化器更新。

学习率影响优化器的更新步幅。在参数、梯度和Adam状态相同的一次更新中，0.0003对应0.001的30%步幅；后续两组训练轨迹会不同，不能把最终参数变化简单看成固定0.3倍，也不能预先保证较小学习率更好。

## 5. train、eval、no_grad 与数据用途

`model.train()`设置训练模式；本项目ResNet18的BatchNorm在训练时使用批次统计并更新运行统计。`model.eval()`切换评估模式，BatchNorm使用已有运行统计。`torch.no_grad()`关闭评估过程的梯度记录；它与模式切换各自负责不同工作，不能互相替代。

训练集用于更新参数，训练准确率用于观察模型对已见图片的表现。验证集用于比较设置和选择best；官方测试集用于报告所选配置的测试表现。训练准确率很高也可能只是更适合已见图片，因此还需查看验证指标。

早期基线曾用全部50,000张官方训练图片训练，记录了65.93%的官方测试准确率。阶段9之后另行划分训练/验证集，用验证指标选模型。82.46%是验证准确率，后续固定该组最佳权重测得官方测试准确率81.48%；不把它与早期基线直接当成同条件提升。

`best`保存验证准确率最高的权重，同分保留较早轮；`last`保存最后一轮。当前各组最好都在第5轮，因此这次best与last对应同一轮，但两种保存规则仍有不同用途。现有权重为模型state_dict，不含优化器状态，脚本没有实现断点续训。

## 6. 增强、泛化与 loss 的解释

阶段9的增强B组使用随机裁剪、水平翻转和ToTensor，验证与训练准确率评估均不使用随机增强。增强在原标签保持的设定下提供不同视图，意图是减少对固定位置或外观的依赖，实际效果仍需比较。

本次SimpleCNN训练5轮，增强组验证准确率为63.18%，低于无增强组的65.63%。其训练与验证准确率差距较小，但两项准确率也都较低，因此“差距小”不足以证明它更好，更不能据此否定其他增强或训练预算。

准确率只统计预测类别是否正确，CrossEntropyLoss还考虑模型对真实类别的支持程度。因此准确率上升而平均loss略升可以同时发生；仅凭汇总指标无法确认哪些具体图片造成变化。

如果训练表现高而验证表现低，可能存在过拟合，也可能涉及两组数据的分布、预处理或评估实现差异。先核对相同预处理、eval模式、数据索引和标签，再结合逐轮曲线判断；不凭一次差距就确诊原因。

| SimpleCNN / 适配ResNet18 | 65.63% / 81.37% | 本次同条件对照中，ResNet18高15.74个百分点；平均每轮训练时间约4.98倍 |

增强和学习率对照分别复制本次共同初始状态，各组创建新优化器，并保持相同数据划分与样本顺序。不同模型结构的参数形状不同，模型对照使用各自独立初始化，不能说两种结构拥有相同参数。

训练耗时来自本机的训练循环计时，不代表推理速度。每组对照只有一次已记录的配对运行，尚未进行多种子重复比较或确定全局最佳设置。改变模型、数据、轮数等条件，需要新的对应证据。

| 修改目标 | 首先查看 | 同时核对 |
| --- | --- | --- |
| 学习率 | 阶段12的GROUPS和run_group创建Adam的地方 | 两组共同初值、新优化器及保存配置 |

| 模型结构 | models中的定义或构造函数 | 输出10类、输入尺寸、参数量和权重兼容性 |
| 准确率统计 | stage6_evaluate.py中的evaluate | 预测维度、正确数量及图片总数 |
| 错误分析使用的模型 | 阶段11的SOURCE_RUN和权重路径 | 配置、固定索引及权重来源一致 |

### 跨文件轮数显示：当前问题的直接解释与修法

阶段12的外层循环读取本文件的 `NUM_EPOCHS`。它调用的 `train_one_epoch` 定义在阶段10，该函数打印总轮数时读取阶段10模块中的 `NUM_EPOCHS`。导入函数不会自动让它读取调用文件里的同名变量。

目前两文件都是5，因此现有配置下显示一致。仅假设把阶段12改10、阶段10保持5，第6轮的批次进度可能显示 `Epoch 6/5`，阶段12轮末摘要则显示 `Epoch 6/10 completed`。这属于总轮数显示的配置来源不一致，不能仅凭日志分母判断实际循环仍为5轮。

便于复用的修法是：为共享训练函数增加 `total_epochs` 参数，进度显示使用这个参数；阶段10和阶段12的调用处分别传入自己的 `NUM_EPOCHS`。这样实际循环与显示使用同一份实验配置，无须让两个独立实验长期手动同步全局常量。若以后改轮数，也应同步带有固定“5轮”文字的帮助说明。

本次只给出修改依据，未将此改造应用到源码，未改变当前5轮配置。该潜在显示问题不改变已保存实验的实际指标。

## 9. 排错顺序与局部修复

先把问题归到环境、数据/路径、Tensor维度或模型/训练实现，再沿产生问题的代码定位。下列情况为排查示例，本轮没有执行这些诊断。

| 类别或现象 | 优先核对 | 局部处理依据 |
| --- | --- | --- |
| 环境：导入失败、设备与预期不同 | 实际解释器、已有报错、模型与数据设备 | Windows使用本机pytorch_dev，不把Mac的.venv当成Windows环境；根据具体报错处理，不先升级全部依赖 |
| 数据/路径：索引或权重找不到 | 脚本定位的项目根目录、文件存在性、SOURCE_RUN/REFERENCE_RUN | 找到正确的既有文件或修正引用，不悄悄重新划分数据 |
| Tensor维度：卷积输入或loss报错 | 图片为[B,3,32,32]，logits为[B,10]，标签为[B]且是整数类别 | 例如[B,32,32,3]是不同轴顺序，应定位产生或转换它的地方；不随意改模型通道去掩盖问题 |
| 模型/训练：loss不下降 | 标签对应、loss输入、backward/step、优化器所绑定的模型参数、梯度及loss是否有限 | 先找更新链是否正确，再根据证据研究学习率等设置，不能直接断言“学习率太小” |
| 训练高、验证低 | 模式、预处理、数据划分、逐轮曲线与类别表现 | 区分实现错误和泛化问题，之后再决定正则化、增强或训练预算等后续实验 |
| 日志与配置不一致 | 打印语句和控制实际循环的变量各来自哪里 | 分别确认显示与实际执行，不由一个显示字段推断整次运行失效 |

loss不下降时，沿“读取图片和标签 → logits与loss → 梯度 → 参数更新 → 指标统计”逐段寻找异常。假如优化器绑定的是旧模型而forward使用新模型，继续训练更久无法解决这种更新对象错误；应修正模型与优化器的对应关系。这是说明原因的假设例子，不是本项目已发现的故障。

## 10. 实验状态与证据范围

项目涵盖数据处理、CNN与残差模型、训练和评估、数据增强、对照实验及错误分析，保存了配置、指标、曲线和模型权重。

增强、模型结构和学习率三组实验分别比较一个因素；各组只记录一次配对运行，结论以对应配置、数据划分和5轮训练预算为范围。

最高验证准确率为82.46%，所选模型官方测试准确率为81.48%。尚未进行多随机种子重复实验，单次结果不代表全局最优设置或重复实验的稳定性。
